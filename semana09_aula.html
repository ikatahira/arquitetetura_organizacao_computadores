🔗 O Pipe | — O Coração do PowerShell +20 XP ▾
O pipe | conecta cmdlets em cadeia: a saída do da esquerda vira a entrada do da direita.
No PowerShell, passa objetos, não texto simples — cada item tem propriedades como .Name, .CPU, .Status.
Você pode encadear quantos cmdlets quiser — como uma linha de montagem.
Get-Process
→
Where-Object
→
Sort-Object
→
Select-Object
→
resultado
🔧 Por que isso importa para o técnico? O pipeline é a ferramenta que transforma o PowerShell em uma central de diagnóstico. Em vez de abrir 5 janelas diferentes, você encadeia comandos e obtém exatamente o que precisa em segundos — processos pesados, serviços com falha, arquivos suspeitos. Todo chamado de suporte pode ser triado com um único pipeline bem escrito.
💡
Use o acento grave ` para quebrar uma linha longa em várias — o PowerShell entende que a instrução continua na linha seguinte.
COMANDO Pipeline básico — processos com mais de 10s de CPU
# Exemplo 1 — pipeline simples
PS C:\> Get-Process | Where-Object { $_.CPU -gt 10 }
Saída no terminal

------ ----- ------ ------ -- -----------
248 512.3 480.1 142.8 4120 chrome
64 198.5 220.4 89.2 2380 Code
32 88.1 102.3 24.7 1844 powershell
12 45.2 62.8 18.3 3100 Teams
🔍 Entendendo cada parte do comando
Get-Process
Coleta todos os processos em execução no momento — cada processo é um objeto com propriedades como nome, uso de CPU, memória RAM ocupada e ID. É como abrir o Gerenciador de Tarefas, mas em forma de dados que você pode filtrar e exportar.
🖥️ Técnico de TI Use para identificar processos travados, consumindo CPU/RAM excessiva ou de origem suspeita.
|
O pipe — passa o resultado para o próximo cmdlet. Em vez de mostrar tudo na tela, ele envia cada processo como "objeto" para o Where-Object processar. Pense em uma esteira de fábrica: cada peça passa para a próxima etapa.
Where-Object
Filtra os objetos recebidos de acordo com uma condição que você define dentro de { }. Só os objetos que passam na condição seguem adiante — os demais são descartados.
🖥️ Técnico de TI É o "filtro de suporte": em vez de ver 80 processos, você vê só os que importam.
$_
Representa o processo atual sendo avaliado. O PowerShell pega cada processo da lista e coloca em $_ para testar a condição. Se passar, o processo continua; se não, é eliminado. O ponto . depois acessa uma propriedade: $_.CPU lê o consumo de CPU daquele processo específico.
-gt 10
-gt significa "greater than" (maior que). O número 10 aqui é em segundos de CPU acumulados — não porcentagem. Processos que consumiram mais de 10 segundos de CPU desde que foram iniciados aparecem no resultado.
COMANDO Pipeline completo — top 5 processos por CPU com colunas específicas
PS C:\> Get-Process `
  | Where-Object { $_.CPU -gt 5 } `
  | Sort-Object CPU -Descending `
  | Select-Object Name, CPU, Id `
  | Select-Object -First 5
Saída no terminal — apenas 5 linhas, só as colunas que você pediu
Name CPU Id

Code 89.2 2380
powershell 24.7 1844
Teams 18.3 3100
explorer 11.1 2104
🔍 Entendendo cada parte do comando
Get-Process
Ponto de partida: coleta todos os processos em execução com todas as suas propriedades. Daqui em diante, cada etapa do pipeline vai refinando esse conjunto de dados.
` (acento grave)
Quebra de linha visual. O acento grave no final de cada linha diz ao PowerShell: "o comando continua na linha seguinte". Serve apenas para deixar o código mais legível — não afeta o resultado. Sem ele, tudo ficaria em uma linha só e seria difícil de ler.
Where-Object {$_.CPU -gt 5}
Primeira filtragem: elimina todos os processos que consumiram 5 segundos ou menos de CPU. Isso reduz a lista antes de ordenar — boa prática para melhorar o desempenho.
🖥️ Técnico de TI Filtrar antes de ordenar economiza processamento, especialmente em servidores com centenas de processos.
Sort-Object CPU
Ordena os processos restantes pela propriedade CPU, do menor para o maior por padrão.
-Descending
Inverte a ordem: do maior para o menor. Sem este parâmetro, o processo com menos CPU apareceria primeiro — o que não é o que queremos em um diagnóstico de consumo alto.
Select-Object Name, CPU, Id
Escolhe quais colunas mostrar. Por padrão, Get-Process retorna dezenas de propriedades (memória virtual, handles, threads...). Aqui selecionamos apenas Name (nome do processo), CPU (segundos de processador) e Id (número identificador do processo — útil para encerrar com Stop-Process -Id).
Select-Object -First 5
Limita o resultado aos 5 primeiros itens da lista já ordenada — que são exatamente os 5 processos com maior consumo de CPU. O parâmetro -First é como dizer "me dê apenas os N primeiros".
🖥️ Técnico de TI Em vez de vasculhar 80 processos, você recebe direto o ranking dos vilões da lentidão.
🔍 Filtragem — Where-Object e Operadores +20 XP ▾
Where-Object filtra objetos. Dentro do bloco {}, use $_ para representar cada item.
Operadores: -eq igual · -ne diferente · -gt maior · -lt menor · -like padrão com * · -match regex
Sintaxe curta: Where CPU -gt 100 (sem $_.) — disponível no PowerShell 3+.

🔍 Entendendo cada parte do comando
Get-Service
Lista todos os serviços do Windows — sejam eles em execução, parados ou pausados. Serviços são programas que rodam em segundo plano: servidor de impressão, cliente DHCP, antivírus, atualizações do Windows, etc. Sem filtro, retorna mais de 200 serviços.
🖥️ Técnico de TI Usado para verificar se serviços críticos estão ativos após uma reinicialização ou falha.
$_.Status
$_ é o serviço atual sendo avaliado. .Status acessa a propriedade que informa o estado desse serviço. Os valores possíveis são: Running (em execução), Stopped (parado) e Paused (pausado).
-eq 'Running'
-eq significa "equal" (igual a). O valor 'Running' deve estar entre aspas simples porque é um texto (string), não um número. O PowerShell compara o Status de cada serviço com esse texto — só passa quem for exatamente Running.
COMANDO Processos pesados — sintaxe curta (PowerShell 3+)
PS C:\> Get-Process | Where-Object CPU -gt 100
Saída — processos que consumiram mais de 100s de CPU
NPM(K) PM(M) WS(M) CPU(s) Id ProcessName
------ ----- ----- ------ -- -----------
248 512.3 480.1 142.8 4120 chrome
64 198.5 220.4 108.2 2380 Code
🔍 Entendendo cada parte do comando
Where-Object CPU -gt 100
Sintaxe simplificada (sem chaves { } e sem $_.). Disponível a partir do PowerShell 3. Em vez de escrever Where-Object { $_.CPU -gt 100 }, você pode escrever diretamente o nome da propriedade (CPU), o operador (-gt) e o valor (100). Mais rápido de digitar, mesma funcionalidade.
🖥️ Técnico de TI Use a sintaxe curta para comandos rápidos no terminal; use a com chaves em scripts para maior clareza.

🔍 Entendendo cada parte do comando
Get-ChildItem 'C:\Windows'
Lista o conteúdo da pasta C:\Windows — equivalente ao dir do CMD. O caminho entre aspas define qual pasta listar. Cada arquivo e pasta retornado é um objeto com propriedades como Name, Extension, Length (tamanho em bytes), LastWriteTime (data de modificação).
$_.Extension
Acessa a extensão do arquivo atual — a parte depois do ponto: .log, .exe, .txt. Inclui o ponto, então compare sempre com '.log' (com o ponto), não 'log'.
🖥️ Técnico de TI Essencial para buscar arquivos de log de erros, instalações e atualizações em toda a pasta do Windows.
COMANDO Serviços cujo nome começa com "W" — operador -like
PS C:\> Get-Service | Where-Object { $_.Name -like 'W*' }
Saída — serviços começando com W
Status Name DisplayName
------ ---- -----------
Running WinRM Windows Remote Management
Running Wecsvc Windows Event Collector
Stopped WerSvc Windows Error Reporting Service
Running WSearch Windows Search
🔍 Entendendo cada parte do comando
$_.Name
Acessa o nome técnico do serviço — não o nome amigável (DisplayName). Por exemplo: Spooler é o nome técnico; "Spooler de Impressão" é o DisplayName. Use $_.Name quando souber o nome interno do serviço.
-like 'W*'
-like usa curingas (wildcards). O asterisco * representa "qualquer sequência de caracteres". Então 'W*' significa: qualquer coisa que comece com W. Outros exemplos: '*srv' encontra nomes que terminam com "srv"; '*win*' encontra qualquer nome que contenha "win" em qualquer posição.
🖥️ Técnico de TI Útil quando você sabe parte do nome do serviço, mas não o nome completo exato.
🔧 Por que isso importa para o técnico? Filtrar é a diferença entre ver 300 serviços na tela e ver os 2 que estão com problema. Com Where-Object você identifica serviços parados, processos travados ou arquivos antigos em segundos — sem precisar vasculhar listas enormes manualmente.
⚠️
Lembre-se: o operador -like usa * como curinga (qualquer coisa). Já -match usa expressões regulares completas — mais poderoso, mas mais complexo.

📦 Variáveis e a Variável Especial $_ +20 XP ▾
Variáveis começam com $. Armazenam qualquer coisa: texto, número, lista de objetos ou resultado de cmdlet.
$_ (ou $PSItem) representa o objeto atual dentro de um pipe ou laço. Você vai usar isso o tempo todo!
Variáveis automáticas: $env:COMPUTERNAME (nome do PC), $env:USERNAME (usuário), $PSVersionTable (versão do PS).
COMANDO Armazenar resultado em variável e reutilizar
PS C:\> $processos = Get-Process
PS C:\> $processos.Count # quantos processos?
Saída — total de processos em execução
87

# Agora filtramos da variável — sem precisar chamar Get-Process de novo!

🔧 Por que isso importa para o técnico? Variáveis permitem capturar informações do sistema e reutilizá-las sem repetir comandos. $env:COMPUTERNAME, $env:USERNAME e resultados de cmdlets armazenados em variáveis formam a base de qualquer script de inventário, auditoria ou manutenção automatizada que você vai criar na vida profissional.

⚠️ Tente primeiro! ▾
M1
Relatório de Processos — top10cpu.csv
Estratégia: Get-Process retorna objetos com propriedade CPU. Sort-Object -Descending + Select-Object -First 10 filtram os maiores. Export-Csv salva sem o tipo .NET (parâmetro -NoTypeInformation).
# Missão 1 — Pipeline: processos com mais CPU → CSV Get-Process | Sort-Object -Property CPU -Descending | Select-Object -First 10 -Property Name, CPU, Id | Export-Csv -Path '.\top10cpu.csv' -NoTypeInformation -Encoding UTF8 # Conferir o resultado Import-Csv '.\top10cpu.csv' | Format-Table
Atenção: processos sem janela aberta (serviços) costumam ter CPU = null. Se aparecer erro, adicione | Where-Object { $_.CPU -ne $null } antes do Sort-Object.
M2
Auditoria de Serviços — rodando.csv e parados.csv
Estratégia: Where-Object filtra pelo Status do serviço. Status -eq "Running" para os ativos, -eq "Stopped" para os parados. Dois Export-Csv com caminhos diferentes.
# Missão 2 — Auditoria separada por status Get-Service | Where-Object { $_.Status -eq 'Running' } | Select-Object Name, Status, DisplayName | Export-Csv -Path '.\rodando.csv' -NoTypeInformation -Encoding UTF8 Get-Service | Where-Object { $_.Status -eq 'Stopped' } | Select-Object Name, Status, DisplayName | Export-Csv -Path '.\parados.csv' -NoTypeInformation -Encoding UTF8 # Quantos em cada grupo? Write-Host "Rodando: $((Import-Csv .\rodando.csv).Count)" Write-Host "Parados: $((Import-Csv .\parados.csv).Count)"
Variação aceita: pode-se usar -eq 'Stopped' ou -ne 'Running' — ambos funcionam, mas o primeiro é mais explícito e legível.
M3
Inventário Rápido do Sistema — 5 linhas
Estratégia: variáveis de ambiente ($env:) fornecem PC e usuário sem precisar de cmdlets pesados. Get-PSDrive filtra o drive C: e usa a propriedade Free (em bytes) — dividir por 1GB converte para gigabytes legíveis.
# Missão 3 — Inventário em 5 linhas $pc = $env:COMPUTERNAME $usuario = $env:USERNAME $livreGB = [math]::Round((Get-PSDrive C).Free / 1GB, 2) Write-Host "PC : $pc" Write-Host "Usuário : $usuario" Write-Host "Livre C : $livreGB GB"
Por que [math]::Round? A divisão por 1GB retorna muitas casas decimais. O Round arredonda para 2 casas, deixando a saída limpa. O 1GB é uma constante embutida do PowerShell (= 1.073.741.824 bytes).
