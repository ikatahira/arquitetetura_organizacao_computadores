🌐 O que é PowerShell Remoting? +20 XP ▾
PowerShell Remoting permite executar comandos em computadores remotos como se estivesse localmente. Usa o protocolo WSMan (WS-Management) via HTTP (porta 5985) ou HTTPS (5986).
Em domínios Windows pode ser habilitado via Política de Grupo (GPO) para todos os computadores de uma só vez — sem precisar ir máquina por máquina.
O serviço que habilita o Remoting é o WinRM (Windows Remote Management). Você precisa habilitá-lo tanto no PC que envia quanto no que recebe.
💡
Analogia para fixar: é como ter um controle remoto universal para todos os computadores da rede — você digita aqui, executa lá. Sem precisar abrir Remote Desktop, sem precisar sentar na frente de cada máquina.
🔧 Por que isso importa para o técnico? Imagine uma escola com 40 computadores no laboratório. Sem Remoting, você precisa caminhar até cada um para verificar se o Windows Update está ativo, se o antivírus está rodando, ou para instalar um programa. Com Remoting, você faz tudo em segundos do seu próprio computador. É a diferença entre trabalhar como técnico júnior e trabalhar como administrador de sistemas.
⚙️ Habilitando o WinRM — Passo a Passo +20 XP ▾
Enable-PSRemoting -Force configura tudo automaticamente: inicia o serviço WinRM, cria regras de firewall e define as permissões. Execute como Administrador.
Fora de domínio, você precisa adicionar os IPs dos PCs remotos na lista de TrustedHosts — caso contrário o Windows recusa a conexão por segurança.
Test-WSMan verifica se o WinRM está respondendo em um computador — use para testar antes de tentar executar comandos remotos.
PASSO 1 Habilitar o Remoting (executar como Administrador)
PS C:\> Enable-PSRemoting -Force

💻 Sessões Remotas na Prática +20 XP ▾
Invoke-Command — executa bloco de script em 1 ou vários PCs remotos de uma vez. Ideal para automação em lote: você passa uma lista e ele executa em todos simultaneamente.
Enter-PSSession — abre sessão interativa (como SSH). O prompt muda para [PC-01]: PS C:\> mostrando que você está "dentro" do computador remoto.
New-PSSession cria sessão persistente reutilizável — você autentica uma vez e usa várias vezes. Sempre feche com Remove-PSSession ao terminar.
EXEMPLO Invoke-Command — executar em PC remoto
# Executar comando pontual em PC remoto
Invoke-Command -ComputerName 'PC-LAB01' -ScriptBlock {
  Get-Process | Sort-Object CPU -Descending | Select-Object Name, CPU -First 5
}
Saída — processos do PC-LAB01 mais consumidores de CPU

EXEMPLO Invoke-Command — múltiplos PCs ao mesmo tempo
# Verificar espaço em disco em 3 PCs simultaneamente
$pcs = @('PC-LAB01', 'PC-LAB02', 'PC-LAB03')

Invoke-Command -ComputerName $pcs -ScriptBlock {
  $livreGB = [math]::Round((Get-PSDrive C).Free / 1GB, 1)
  "$env:COMPUTERNAME — Disco C: $livreGB GB livre"
}
Saída — resultado dos 3 PCs em paralelo

EXEMPLO New-PSSession — sessão persistente e reutilizável
# Criar sessão persistente (autentica uma vez)
$sessao = New-PSSession -ComputerName 'PC-LAB01'

# Usar a sessão várias vezes sem reautenticar
Invoke-Command -Session $sessao -ScriptBlock { $env:COMPUTERNAME }
Invoke-Command -Session $sessao -ScriptBlock { Get-Date }

# SEMPRE feche ao terminar — libera recursos do servidor remoto
Remove-PSSession $sessao
Saída das duas chamadas
PC-LAB01

segunda-feira, 15 de maio de 2026 14:32:08

(sessão encerrada — recursos liberados no servidor remoto)
🔧 Por que isso importa para o técnico? Com Invoke-Command e uma lista de 40 IPs, você verifica o status de todos os PCs do laboratório em segundos. Sem Remoting, isso levaria o dia inteiro. Scripts de auditoria remota são uma das habilidades mais valorizadas em ambientes corporativos e educacionais — e é exatamente o que a Avaliação 2 vai exigir.
🔒 Segurança no Remoting +20 XP ▾
Princípio do menor privilégio: use contas dedicadas para gerenciamento remoto com apenas as permissões necessárias. Nunca use a conta de Administrador de Domínio para scripts automatizados.
Use HTTPS (porta 5986) em vez de HTTP para criptografar o tráfego em redes não confiáveis. Em HTTP, credenciais e comandos trafegam em texto claro na rede local.
Audite conexões remotas nos logs de eventos — isso é obrigatório em empresas reguladas (bancos, saúde, governo) e importante para investigar incidentes de segurança.
SEGURANÇA Auditar conexões remotas via logs de eventos
# Verificar quem se conectou remotamente
Get-WinEvent -LogName 'Microsoft-Windows-WinRM/Operational' -MaxEvents 10 |
  Select-Object TimeCreated, Message |
  Format-List
Saída — histórico de conexões WinRM
TimeCreated : 15/05/2026 14:30:12
Message : Creating WSMan Session. The connection string is: localhost

TimeCreated : 15/05/2026 14:28:55
Message : WSMan operation ShellCommand completed successfully
⚠️
Nunca faça: não use credenciais de Administrador de Domínio para tarefas rotineiras. Não salve senhas dentro de scripts (.ps1). Não habilite TrustedHosts = "*" em redes corporativas — cria risco de ataques man-in-the-middle.
🔧 Por que isso importa para o técnico? Segurança no Remoting não é opcional — é responsabilidade profissional. Um técnico que habilita o WinRM sem configurar corretamente abre uma porta para atacantes na rede. Em empresas, configurações inseguras de WinRM são um vetor comum de movimentação lateral em ataques. Conhecer os riscos faz parte do kit básico de todo técnico em informática.

M1
Habilitando e Testando o WinRM
Estratégia: Execute cada comando em sequência. Enable-PSRemoting só funciona como Administrador — clique com botão direito no ícone do PowerShell e escolha "Executar como Administrador". Confirme com Y quando perguntado.
# Passo 1 — Abrir PowerShell como Administrador, depois: Enable-PSRemoting -Force # Passo 2 — Verificar se o serviço WinRM está rodando Get-Service WinRM # Resultado esperado: # Status Name DisplayName # Running WinRM Windows Remote Management (WS-Management) # Passo 3 — Testar conectividade com o próprio PC (localhost) Test-WSMan localhost # Resultado esperado: bloco com versão do protocolo WinRM # wsmid : http://schemas.dmtf.org/wbem/wsman/1/... # ProtocolVersion: http://schemas.dmtf.org/wbem/wsman/1/...
Se Test-WSMan não responder: verifique o Firewall do Windows — Enable-PSRemoting cria a regra automaticamente, mas políticas de grupo em ambientes de domínio podem bloqueá-la. Tente netsh advfirewall firewall show rule name="Windows Remote Management (HTTP-In)" para confirmar.
M2
Gerenciamento Remoto de Serviços via localhost
Estratégia: Em laboratório sem outro PC, usamos localhost como destino remoto — funciona perfeitamente para testar Remoting. A sessão persistente com New-PSSession economiza autenticação repetida.
# Missão 2 — Parte A: Listar serviços remotamente Invoke-Command -ComputerName localhost -ScriptBlock { Get-Service | Where-Object Status -eq 'Running' | Select-Object -First 5 } # Parte B: Parar e iniciar o Spooler remotamente Invoke-Command -ComputerName localhost -ScriptBlock { Stop-Service Spooler -Force } Invoke-Command -ComputerName localhost -ScriptBlock { Start-Service Spooler } Invoke-Command -ComputerName localhost -ScriptBlock { (Get-Service Spooler).Status } # Parte C: Sessão persistente — autentica uma vez, usa várias $s = New-PSSession -ComputerName localhost Invoke-Command -Session $s -ScriptBlock { $env:COMPUTERNAME } Invoke-Command -Session $s -ScriptBlock { Get-Date } Invoke-Command -Session $s -ScriptBlock { (Get-Process).Count } # Sempre feche a sessão ao terminar! Remove-PSSession $s
Por que usar localhost? O WinRM funciona igualmente para conexões locais — você exercita exatamente o mesmo código que usaria em PCs remotos reais, só mudando localhost pelo IP ou nome do PC de destino.
M3
Script de Auditoria Remota com Export-Csv
Estratégia: Invoke-Command com uma lista de computadores executa o bloco em paralelo. O try/catch dentro do ScriptBlock trata PCs offline — o parâmetro -ErrorAction Stop é obrigatório para que o catch funcione. Export-Csv salva o resultado.
# Missão 3 — Script de auditoria remota com CSV $computadores = @('localhost') # adicione mais nomes/IPs aqui $resultado = Invoke-Command -ComputerName $computadores -ScriptBlock { try { $os = Get-CimInstance Win32_OperatingSystem -ErrorAction Stop [pscustomobject]@{ PC = $env:COMPUTERNAME SO = $os.Caption UltimoBoot = $os.LastBootUpTime Processos = (Get-Process).Count Status = 'OK' } } catch { [pscustomobject]@{ PC = $env:COMPUTERNAME SO = '-' UltimoBoot = '-' Processos = 0 Status = "ERRO: $($_.Exception.Message)" } } } -ErrorAction SilentlyContinue $resultado | Select-Object PC, SO, UltimoBoot, Processos, Status | Export-Csv -Path '.\auditoria.csv' -NoTypeInformation -Encoding UTF8 Write-Host "Auditoria salva em auditoria.csv — $($resultado.Count) PC(s) verificado(s)" $resultado | Format-Table -AutoSize
Para testar com PC offline: adicione um nome inexistente à lista, como 'PC-INEXISTENTE'. O -ErrorAction SilentlyContinue no Invoke-Command evita que PCs inacessíveis parem o script — e o CSV registrará o erro para cada um.
